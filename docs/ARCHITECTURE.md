# 架构（v2，2026-10-22 起）

## 为什么重写

旧实现是 AstrBot 插件：`main.py` 4600 行里混着门控、提示词、工具、玩法，
而且进程内存 779MB 里 97% 是 AstrBot 框架。新的核心自己实现协议与管线，
代码量小、启动快、内存低，插件化后每个能力可以独立发版。

## 分层

```
┌──────────── core（本仓库）────────────┐
│ onebot/   反向 WS + 事件模型 + action │
│ pipeline/ 门控阶段（每段一个函数）      │
│ llm/      chat / chat_tools           │
│ plugin/   插件宿主（JSON-RPC）         │
└───────────────┬───────────────────────┘
                │ unix socket + JSON-RPC（进程边界 = 语言自由）
   ┌────────────┼─────────────┬──────────────┐
persona       turtle_soup   websearch    （任意语言）
```

## 关键决策

1. **QQ 接入只做 OneBot v11**：SnowLuma 反向 WS，一个连接足够单账号。
2. **插件走进程边界**：不是 in-process import。理由：插件是"慢调用"（LLM 判题/搜索/生图，
   几百毫秒到几十秒），IPC 的亚毫秒开销可忽略；换来的是崩溃隔离、独立发版、任意语言。
   参考现有 `qqbot-asr.service`（unix socket + JSON 行）已经验证过这套模式。
3. **核心不实现玩法**：海龟汤、人格卡内容、表情库都是插件。
4. **核心默认人格只有 4 行**：没装人格插件也能说话，只是没个性。
