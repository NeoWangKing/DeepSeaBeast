# 回合模型（turn）

一条消息进来，到她说完，叫**一个回合**。回合有身份证、有预算、能被打断。

## 为什么要显式建模

| 问题 | 没有回合模型的后果 |
|---|---|
| 群友补了一句 | 她还在回答上一句，答非所问 |
| 说"算了别说了" | 她照样把 4 条气泡发完 |
| 模型死循环 | 一直烧 token，没有上限 |
| 出问题排查 | 日志里看不出"哪几条属于同一次回复" |

## 生命周期

```
消息到达
   │
   ├─ 上一回合还在跑？ → 置 cancelled（协作式取消），日志记"被新消息打断"
   │
   ├─ 新建 TurnContext(id, 预算, 截止时间)
   │
   ├─ 管线：白名单 / 频率 / 决定 / 连发合并
   │     ├─ "话没说完" → defer，等 typing_wait_sec 再重放
   │     └─ 说完了 → 继续
   │
   ├─ 上下文装配 → 模型 → 工具 → … （每个检查点看 should_stop）
   │
   └─ 收尾：finished=True，日志打一行 ctx.describe()
```

## 取消是协作式的

只置标记 `ctx.cancelled = True`，由检查点停下：

- `agent.run_turn()` 每轮模型调用前
- 每次工具调用前
- `Turn._do_send()` 每次真的要发之前

**已经在路上的气泡收不回**——但被打断后**不会**再补发，这正好是人的样子。

## 预算（`[turn]`）

```toml
max_tokens  = 20000   # 单回合 token 上限（所有轮次累计）
max_seconds = 45      # 墙钟上限
max_rounds  = 6       # 模型-工具循环次数
max_sends   = 4       # 最多几条气泡
```

超了就在检查点停下，`stop_reason` 记成 `budget:15000/20000` / `timeout:47s` / `cancelled:新消息打断`。

## "她话没说完"怎么办

`core/typing.py` 做启发式判断：

```
没说完 ← 结尾是连接词（然后/因为/但是/我/你…）、结尾是逗号或省略号、
         或者短得离谱又没有标点（"我跟你"）
说完了 ← 结尾有句号/问号/感叹号，或常见完整短句（"在吗"/"你好"/"好的"）
```

策略：

| 情况 | 行为 |
|---|---|
| 第一条明显没说完 | **等**（最多 `typing_wait_sec`），期间她再补就继续等 |
| 补完整了 | **立刻回合并后的整句**（相当于"插嘴"：意思已经清楚，不用再等） |
| 一直没下文 | 等满 `typing_wait_sec` 后正常回 |
| 说完了 | 立刻回 |

**所有通道一致**（QQ / 终端 / 脚本）：等待逻辑在核心里，不区分来源。

### 终端这类"可能立刻 EOF"的通道

`printf "…" | nc` 会在发出后立刻 EOF。为了让"等她说完再重放"的回合还能把话送出去，
通道需要在 EOF 后**等运行时通知 idle** 才断开：

```
读循环结束（EOF）
   → 等本连接上的后台回合
   → 等 idle 信号（运行时的回合都结束了）
   → 再关闭连接
```

## 追踪

所有日志都带 `turn id`：

```
[runtime] [g100000001] 回合 t-20261023-002543-b1d5 判断 '在吗' → reply
[agent]   t-20261023-002543-b1d5 工具 decide(...) → 行，按这个回：…
[agent]   token：命中 3328 / 总计 4349（76%）
[agent]   t-20261023-002543-b1d5 工具 send_message("在的") → 已发出（1/4）
[runtime] [g100000001] 回合 t-20261023-002543-b1d5 完成：'在的'
[runtime] [g100000001] t-20261023-002543-b1d5 rounds=3 sends=1 tokens=4349 elapsed=2.1s
```

排查一条消息的全过程：

```bash
journalctl -u deepsea-beast | grep t-20261023-002543-b1d5
```
