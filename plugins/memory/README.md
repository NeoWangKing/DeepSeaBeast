# memory（记忆空间）

只管一件事：**维护记忆空间**——一个全局的 + 每个会话（群/私聊/终端）各一份。
**记什么、改什么、什么时候记，由模型决定**；插件只提供存储、整理和注入。

## 空间

| 空间 | 内容 | 例子 |
|---|---|---|
| `global` | 放之四海皆准的 | "我不该在群里贴长代码"、关于主人的稳定偏好 |
| `<scope_key>` | 只在这里成立的 | 本群氛围、成员特点、群里的梗 |

`scope_key` 由核心给（`g<群号>` / `p<QQ>` / `cli`）。

## 数据（都在 `$DEEPSEA_PLUGIN_DATA`）

```
spaces/global.json          全局记忆
spaces/g1.json              某个群的记忆
buffer/g1.jsonl             还没整理的原始素材（滚动保留最近 80 条）
state.json                  上次整理时间
```

一条记忆长这样：

```json
{"id": "m-0003", "text": "某人在写一个 Rust 项目", "importance": 4,
 "tags": ["成员"], "created": 1792..., "updated": 1792..., "uses": 0, "source": "g1"}
```

## 三个动作

**① 攒素材**（事件）
订阅 `message.received`，把每条消息按会话写进 `buffer/<scope>.jsonl`。

**② 整理**（后台任务，默认 15 分钟）
攒够 6 条、或最老的一条超过 30 分钟 → 把「已有记忆 + 最近对话」交给模型，
模型返回操作：

```json
{"ops": [
  {"op": "add",    "space": "session", "text": "...", "importance": 4, "tags": ["成员"]},
  {"op": "update", "space": "global",  "id": "m-0003", "text": "...", "importance": 5},
  {"op": "delete", "space": "session", "id": "m-0007", "reason": "过时了"}
]}
```

模型觉得没什么可记就返回 `{"ops": []}`——**"记不记"是模型的判断，不是插件的规则**。
相同文本不会重复写入。

**③ 注入**（`get_context`）
按「字面相关性（重叠词）× 3 + 重要度 + 新鲜度」排序：
全局取 6 条、当前会话取 8 条，拼成

```
【长期记忆】
- 我不该在群里贴长代码
【关于这里的记忆】
- 某人在写一个 Rust 项目
```

## 每天一次的压缩

空间超过 60 条时，让模型合并重复、丢掉过时的，只保留 ≤50 条。

## 不用向量、不加依赖

排序是字面重叠 + 重要度 + 新鲜度，全部标准库。以后要上向量检索，
换掉 `rank()` 和存储层即可，协议不变。

## 配置

插件本身不读配置，靠核心在 `hello` 里给的 `llm`（`base_url` / `model` / `api_key_file`）。
模型不可用时插件仍会攒素材（只是不整理），日志里会写"先只攒素材"。
